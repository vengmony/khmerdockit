# Getting help

There are a few different ways to get help with **KhmerDocKit** depending
on what you need. Pick the one that matches.

## I have a question

* **General "how do I…" questions** — open a
  [GitHub discussion](https://github.com/khmerdoc/khmerdockit/discussions)
  with the `q-a` label. Don't open an issue for usage questions.
* **"Is this a bug or am I holding it wrong?"** — start with a
  discussion; if it turns out to be a bug, we'll convert it.

## I found a bug

* Open a
  [bug report](https://github.com/khmerdoc/khmerdockit/issues/new?template=bug_report.yml).
* Please **do not** include real receipts or private data — only
  synthetic samples, or a clear description of the failure.

## I want a new feature / new document template

* Open a
  [feature request](https://github.com/khmerdoc/khmerdockit/issues/new?template=feature_request.yml) or a
  [template request](https://github.com/khmerdoc/khmerdockit/issues/new?template=document_template_request.yml).
* If you want to build it yourself, say so in the issue and we'll tag
  it as `good first issue` / `help wanted` if it fits.

## I found a security issue

See [SECURITY.md](./SECURITY.md). **Do not** open a public issue for
security problems.

## I want to contact the maintainer directly

* For governance / co-maintainer / partnership questions, see
  [MAINTAINERS.md](./MAINTAINERS.md).
* Otherwise, the public channels above are preferred — they let other
  community members benefit from the answer.

## Response time

KhmerDocKit is a small project with one (or a few) volunteer
maintainers. We aim to acknowledge new issues within **5 business
days**, but full triage may take longer. If something is urgent, mark
the issue with the `priority: high` label and explain why.
